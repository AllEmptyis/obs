# Replica
- 데이터를 다른 저장소에 사본을 만들어두는 것
- 사용 목적
	- DR, 장애 대비 등
- 레플리카 방식
	- 동기
		- ex. ceph
		  프라이머리 OSD가 쓰기를 받으면 다른 OSD에 동시 전파
		  전부 커밋된 것을 확인 후 성공 응답
		  단 레플리카 수가 많을 수록 레이턴시 있음
	- 비동기
- RAID, 레플리카, 백업 차이
	- RAID는 디스크 한정 복제
		- raid: 한 서버 내부의 여러 디스크를 하나처럼 사용하는 기술
		  즉 서버 자체가 고장나면 의미가 없음
	- 레플리카 - 시스템(서버,스토리지) 자체 장애 대비, 다른 서버로도 복제 가능
	- 백업
		- 실시간 연동(복제) 아님, 과거 시점의 데이터 복구 용도
- 레플리카 갯수
	- 임의로 설정 가능
	- HCI에서는 기본 2개, 최대 3개 (서버가 총 3대) //그 이상 가능한지는 확인 필요

# 디스크 성능
- 디스크 IOPS (INPUT/Output Operations Per Second)
	- 초당 몇 번의 I/O 요청 처리가 가능한지 (요청 갯수)
	- Read IOPS
		- 초당 읽기 요청 처리 횟수
	- DB, 트랜젝션 처리 등에 중요
- 대역폭
	- 초당 몇 MB/GB의 데이터를 옮길 수 있는지 (데이터의 크기)
	- 10GB 백업 파일을 몇 초만에 읽을 수 있는지?
	- 백업, 대용량 파일 전송 등

# swap 메모리
- 램이 부족할 때 디스크 공간을 임시로 RAM처럼 빌려 쓰는 영역
	- 시스템의 물리 메모리가 다 차면 당장 안쓰는 메모리 페이지를 디스크의 특정 영역(swap)에 옮기고 그 자리를 다른 작업에 사용
	- 다시 필요할 때 swap으로 갔던 데이터를 불러옴
		- swap in / out
- 디스크는 swap보다 수만 배 느리기 때문에 자주 swap을 사용하게 되면 시스템이 느려짐 (swap thrasing)
- 확인 방법
	- free -h 에서 swap에 used 항목 증가 확인
- swap 메모리가 부족할 때
	- thrasing 발생 가능

# 디스크
## 리눅스 블록 디바이스 네이밍
- sdx
	- SCSI 서브시스템으로 연결되는 디스크
	- SATA 방식으로 연결
```
SCSI (Small Computer System Interface)
- 저장장치와 컴퓨터 간 명령을 주고받기 위한 표준 프로토콜
- 명령체계/소프트웨어 규격
  
SATA : 하드웨어 규격 (물리적 규격)
SATA 디스크 --(SATA 전기신호)--> [SATA 컨트롤러] --(PCIe로 변환)--> CPU/메모리

SATA: 전선이 어떻게 생겼고 신호가 어떻게 오가는지
SCSI: 디스크에게 3번 섹터부터 100블록 읽어달라 등 명령

SATA 신호 → SCSI 명령 형식으로 변환 → 커널의 SCSI 서브시스템이 처리
[SATA 디스크] --SATA 전기신호--> [SATA 컨트롤러] --변환--> [libata] --SCSI 명령형식--> [커널 SCSI 서브시스템] --> sda로 인식
```
- nvme0n1
	- NVMe 프로토콜로 연결된 디스크
	- NVMe SSD 전용 (PCle 직결)
```
SATA는 HDD에 맞춰져서 설계된 규격
SSD의 초고속 병렬 처리 능력을 살리기 위해 만들어진 프로토콜

PCle 직결이란?
기존 SATA 방식
SSD ←→ SATA 컨트롤러 ←→ (SATA 버스, 대역폭 제한) ←→ CPU/메모리

NVMe 방식
SSD ←→ PCIe 슬롯 (CPU와 바로 연결된 고속 통로) ←→ CPU/메모리

PCle: 그래픽,네트워크 카드가 꽂히는 컴퓨터에서 가장 빠른 범용 데이터 통로
NVme 방식은 중간 컨트롤러 없이 직결되는 것

NVME는 SATA 변환 과정/SCSI 명령 체계 둘 다 거치지 않음
독자적인 프로토콜 사용
```
- hdx (요즘엔 거의 사용 안함)
	- IDE(PATA) 방식으로 연결된 디스크
		- 병렬 전송
		- SATA는 직렬 전송 // 현재는 거의 직렬전송 방식 사용
- vdx
	- 가상화 환경의 가상 디스크
```
VM의 가상화 방식(디스크 드라이버 설정)에 따라 보통 다르게 나온다

ex.
virtio-blk(kvm/qumu 드라이버) - vda
SATA 에뮬레이션: sda
SCSI 에뮬레이션: sda
NVMe 에뮬레이션: nvme0n1
```

- ISCSI
	- 원격지 스토리지를 로컬 디스크처럼 사용하고자 할 때 주로 사용

# 마이그레이션
- 일반 마이그레이션은 vm을 중지하고 vm의 디스크/메모리 상태를 다른 노드로 복사
- 라이브 마이그레이션은 무중단 마이그레이션
	- 백그라운드에서 메모리 페이지를 대상 노드로 미리 복사 (vm이 실행중이므로 그 사이 바뀐 메모리는 다시 복사 / 이 과정을 pre-copy 방식이라고 함)
	- 남은 메모리가 아주 작아지면 아주 짧은 시간만 vm을 멈추고 마지막 차이분 복사

	- 외부 스토리지에 저장된 형태이기 때문
