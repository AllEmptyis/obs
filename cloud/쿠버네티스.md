# 로드맵
- 1주차 : 환경 구축, 간단한 pod 배포 (1-2장)
	- [ ] 쿠버네티스 개요 / 전체 구조 이해 (control plane, node 등)
	- [ ] 환경 및 클러스터 구축
	- [ ] kubectl 명령어 익히기
	- [ ] pod 정의 파일(YAML) 작성 및 배포
- 2주차: 워크로드 관리 (3-5장) / 웹앱 배포, 설정주입, 서비스 노출 실습
	- [ ] Deployment, Replicaset을 이용한 애플리케이션 관리
	- [ ] Service (ClusterIP, NodePort, LoadBalancer)로 외부 연결
	- [ ] ConfigMap / Secret으로 환경 설정 주입
	- [ ] PVC/PV 기본 개념
- 3주차: 파드 확장 활용 (7-9장)
	- [ ] 멀티 컨테이너 파드, Init 컨테이너 개념
	- [ ] Job / CronJob으로 배치 작업 실행
	- [ ] StatefulSet으로 DB 같은 상태 저장 앱 배포
	- [ ] Deployment 업데이트 전략 (롤링 업데이트, 롤백 실습)

### 컨트롤러 객체


# kubelet
- 파드 실행, 쿠버네티스 노드 데몬
# kubeadm
- 클러스터 설치 도구
- 쿠버네티스 설치 유틸
# kubectl
- 쿠버네티스 관리 CLI
- api server에 명령 전달
# CNI (Containerd Network Interface)
- 쿠버네티스에서 파드간 통신이 되도록 하는 인터페이스
- 컨테이너 표준 규격에 맞도록 설치할 수 있도록 하는 외부 플러그인
	- Calico가 가장 범용적으로 사용됨
- kubelet이 CNI를 호출하고, CNI가 네트워크를 실제 생성한다
# containerd
- 컨테이너를 실제로 실행하는 컨테이너 런타임
	- ex) 컨테이너 생성/종료, 이미지 pull, 네임스페이스 생성
- 쿠버네티스는 containerd가 제공하는 기능 외에도 노드 간 라우팅 등 기능이 필요하기 때문에 CNI 필요
# kube-apiserver
- 마스터노드(control plane)에서 실행 됨
	- 컨테이너(파드) 형식으로 실행
-  모든 쿠버네티스 요청을 처리하는 api 서버

# 역할 정리
```
kubectl
   ↓
kube-apiserver
   ↓
kubelet
   ↓
containerd
   ↓
CNI plugin
   ↓
Linux kernel (veth, bridge, route)
```
