# 환경
- rocky linux9.2 minimal
- 192.168.193.100 위에 kvm으로 가상머신 3대 준비
	- master: 192.168.193.150
	- worker1: 192.168.193.151
	- worker2: 192.168.193.152
# 구성
- /etc/hosts
```
192.168.193.150         master
192.168.193.151         worker1
192.168.193.152         worker2
```
- **swap 비활성화**
	- swapoff -a
	- 영구설정:`/etc/fstab`에서 swap 설정 주석 처리
- 호스트명 변경
	-  hostnamectl set-hostname master
- **커널 모듈 & sysctl 설정**
	- 해당 k8s.conf 파일은 관리자가 임의로 생성하는 것
	- modprobe 명령어를 통해서 쿠버네티스 사용 시 필요한 커널 기능 활성화
```
modprobe overlay
modprobe br_netfilter

---------
위 설정 영구설정
cat <<EOF | tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
----------
cat <<EOF | tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.ipv4.ip_forward                 = 1
net.bridge.bridge-nf-call-ip6tables = 1
EOF

sysctl --system
```

# 설정 설명
- swap off (swap 메모리 비활성화)
	- swap 기능: RAM 부족 시 디스크를 메모리처럼 사용하는 기능
	- kubelet 기본 설정: swap off 되어 있어야 함
	  쿠버네티스는 파드마다 메모리를 정확하게 보장하려 하기 때문에, 스왑 사용 시 스케줄링 계산이 틀어질 수 있음
- systemdCgroup 활성화
	- cgroup이란?
		- 프로세스의 CPU,메모리,I/O 사용량을 제한하는 커널 기능
	- 기본 설정 기준 kubelet은 systemd방식, containerd는 cgroupfs 방식을 사용 
	  (cgroujpfs 방식: cgroup을 파일시스템 형태로 다루는 방식)
	  서로 관리 방식이 다르기 때문에 containerd의 관리 방식을 systemd로 맞춰서 통일하는 것
- sysctl 설정
	- net.bridge.bridge-nf-call-iptables = 1: 브리지 통과 패킷을 iptables가 볼 수 있도록
		- 쿠버네티스 네트워크는 iptables 기반으로 동작
	- net.ipv4.ip_forward: 노드가 라우팅처럼 패킷 포워딩이 가능하도록 (노드에 올라간 파드 간 통신 허용 )
		- 같은 대역이라면 설정 없어도 파드 간 통신 가능
	- net.bridge.bridge-nf-call-ip6tables = 1: ipv6 용도
